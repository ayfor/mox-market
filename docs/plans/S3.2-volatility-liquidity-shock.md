# S3.2 — Volatility & liquidity adjustments + shock annotation

> Story: [Notion S3.2](https://app.notion.com/p/394a7227e26f81d381a2d42db36289b6) · Design: [F3 Market Adjustments](https://app.notion.com/p/394a7227e26f81d0b70fed71139e30a2) (Approved, Josh 2026-10-20; Functionality, Engine API, W1, Fields, Edge cases) · [F1 Price Recommendation Engine](https://app.notion.com/p/394a7227e26f813e8e97f395b70c0eb3) (Approved; Signal definitions, Locked copy table, composition rule, W2) · [F2 Live Evaluation Integration](https://app.notion.com/p/394a7227e26f81b7b3ccf5f51168130c) (Approved; the result panel) · Builds on [S3.1 plan](S3.1-trend-band-shift.md) (PR #20, merged as `5c150b4`) · PR: #21 · Critique: docs/critiques/C1-2026-10-04-phase1-designs.md#C1.11, C1.12, C1.22, C1.23, C1.35, C1.41, C1.47, C1.54, C1.55, C1.56

## Objective
Complete F3 Tier 2. Tier 2 widens the fair band for volatility (`volWiden = clamp(CV / volatileCV, 1.0, volatilityWideningCap)`, CV = F1's `volatility30d`) and caps the whole factor at 2.0 (`min(volWiden × confWiden, 2.0)`, C1.11 = A). Liquidity is staleness: when the newest window row is more than `staleDays` (7) UTC days before `asOf`, Tier 2's confidence caps at low, which also brings the 1.5× low-confidence widening. Tier 2's reason fills its single caveat slot by precedence stale > thin-data > volatility, using F1's locked strings already in `copy.ts`. A shock annotation (`|sevenDayMovePct| ≥ 35`) rides on the signals of both tiers, so the served result carries it whatever `TIER2_ENABLED` says (C1.47 = A), and F2 renders a ⚠️ icon with the locked shock tooltip. The verdict never changes because of a shock. Five params join `RECOMMENDATION_PARAMS` and `PARAMS_VERSION` moves from 208c90c2 to 2d4067ed. `TIER2_ENABLED` stays false.

The S3.1 pivot carries over (S3.1d2): no log is written, so AC-6's "Tier-2 kinds log as `adjustedKind`" stays with S5.1 (S3.2d15).

## Endpoints
None. No route, method or response shape changes. `/[card]` renders the same served recommendation, plus the ⚠️ icon when its signals carry a shock annotation.

## Data Model
None. No schema change, no migration, no database read or write. `docs/architecture/erd.md` is unchanged.

### W2: Inside the engine (one tiered call)
```mermaid
sequenceDiagram
    participant EN as computeTieredRecommendation
    participant T1 as Tier 1 (S1.2 path)
    participant SH as shock.ts
    participant T2 as tier2.ts
    participant RS as reason.ts and copy.ts
    EN->>T1: validate, window, market price, count, signals, bands
    T1->>SH: window rows, params (only when kind is not insufficient_data)
    SH-->>T1: { detected, magnitude, window } or null
    T1-->>EN: tier1 with signals.shockAnnotation
    alt tier1.kind is insufficient_data
        EN-->>EN: tier2 = null
    else
        EN->>T2: tier1, exact 30-day slope, latestAgeDays, params
        Note over T2: stale = latestAgeDays > staleDays; confidence = stale ? low : tier1's
        Note over T2: volWiden = CV null ? 1 : clamp(CV / 0.15, 1, 2); confWiden = 1.5 when low
        Note over T2: wideningFactor = min(volWiden x confWiden, 2); band, asymmetry, clamped shift, whole bp
        T2->>RS: kind, deltaBp, band, confidence, count, trend, stale d, volatility X
        RS-->>T2: primary; trend; one caveat (stale, else thin-data, else volatility).
        T2-->>EN: tier2 (tier1 with kind, confidence, reason, band and thresholds replaced)
    end
```

The strings are `REASON_COPY.stale` and `REASON_COPY.volatility`, verbatim. Tier 1 never passes either, so every Tier-1 reason is unchanged.
- **S3.2d6 (shock definition).** `shockAnnotationOf(windowSnapshots, params)` in `shock.ts`: latest = the newest real window row; ref = the newest real window row whose index is at most `latest.index − shockWindowDays`; null when there is no ref. The trigger compares exact integers, `|latest − ref| × 100 ≥ shockMagnitudePct × ref` (BigInt, as C1.41 compares bands), so ±35 exactly triggers. `magnitude = (latest − ref) × 100 / ref`, multiplication first, so +45 is exactly 45; it is never −0. The result is `{ detected: true, magnitude, window: shockWindowDays }`, and `signals.shockAnnotation` is `ShockAnnotation | null`, null meaning no annotation (F3: "null (no annotation)"). ## Risks
- **R1, parity drift.** Adding `shockAnnotation` to tier1's signals is a new key on every Tier-1 result. Mitigation: AC-6's strip is the only exemption, and the three recordings catch any other change.
- **R2, float factors.** `wideningFactor` and `bandPct` are now arbitrary doubles. Mitigation: thresholds are rounded once to whole bp (C1.41 = A) and asserted exactly; the factor is asserted as `volatility30d / 0.15` from the same signal, and the AC-8 and AC-1 fixtures make CV exactly 0.15 and 0.3.
- **R3, UI copy drift.** The tooltip's "7" is literal in locked copy while the window is a param. Mitigation: T5's test fails if `shockWindowDays` changes without a copy ruling.
- **R4, tooltip on touch.** A hover tooltip does not show on touch screens. Mitigation: the text is also the icon's accessible name and appears on focus; a visible caption would be new copy (S3.2d10).
- **R5, local integration.** No Postgres on this machine; the integration project runs only in CI (C3.3). This story changes no database code.
