# S4.1 — Card classification from Scryfall data

> Story: [Notion S4.1](https://app.notion.com/p/394a7227e26f8185a9aaf418af96a4b7) · Design: [F4 Card Classification](https://app.notion.com/p/394a7227e26f815faf28f2a04a6ccee6) (Approved, Josh 2026-10-30; UI & appearance, Functionality, W1, Fields, Decisions baked in, the 2026-10-30 pivot) · [F1 Price Recommendation Engine](https://app.notion.com/p/394a7227e26f813e8e97f395b70c0eb3) (Approved; `RECOMMENDATION_PARAMS`, `PARAMS_VERSION` (W2), asOf as the caller's UTC date) · [F2 Live Evaluation Integration](https://app.notion.com/p/394a7227e26f81b7b3ccf5f51168130c) (Approved; the result panel, the card header, §Default printing) · Builds on the engine at `f167812` (S3.2 merged as `9ce2bb0`) · PR: #22 · Critique: docs/critiques/C1-2026-10-04-phase1-designs.md#C1.38, C1.50, C1.59, C1.66

## Objective
Derive a `CardCategory` (reservedList, age, popularity, formatProfile, digital) from the Scryfall card object of the printing being priced, with a pure `classify(card, asOf)` in `src/lib/recommendation/classify.ts` that makes no network request. Attach it to `Recommendation.signals.category` on the server path and render it as a chip row near the card identity, each chip with a one-sentence factual tooltip. Four bucket thresholds join `RECOMMENDATION_PARAMS` (`recentPrintingDays` 183, `edhrecTop1Rank` 1000, `edhrecTop2Rank` 5000, `modernEraStart` '2003-07-28'), so `PARAMS_VERSION` moves from 2d4067ed to d722f7b5. Classification is display only: kind, confidence and reason never change.

Pivot (recorded on F4 and S4.1, 2026-10-30; F5 is Draft): no log row is written. AC-5 and AC-4's "the log row's category json is still written" half move to S5.1, which reads `signals.category` (S4.1d12).

## Endpoints
None. No route, method or response shape changes. `/[card]` renders the same panel plus the chip row. No new route handler (the parallel UI lane adds `/api/cards/printings`; this story does not touch it).

## Data Model
None. No schema change, no migration, no database read or write. `docs/architecture/erd.md` is unchanged. The category's log column is S5.1's.

### W2: Inside classify (one call)
```mermaid
sequenceDiagram
    participant SV as buildEvaluation
    participant CL as classify.ts
    participant PR as RECOMMENDATION_PARAMS
    SV->>CL: classify(card, asOf)
    CL->>PR: recentPrintingDays, edhrecTop1Rank, edhrecTop2Rank, modernEraStart
    Note over CL: reservedList = card.reserved === true
    Note over CL: age from released_at: recent, else modern-era or vintage-era, else unknown
    Note over CL: popularity from edhrec_rank: top1000, top5000, longtail, else unranked

    CL-->>SV: CardCategory (never throws; a missing field is that field's default)
```

- **S4.1d4 (classification rules).** `classify(card, asOf, params = RECOMMENDATION_PARAMS)` never throws and never reads the clock. reservedList is `card.reserved === true` and digital is `card.digital === true`. popularity reads `edhrec_rank` only when it is a positive safe integer: ≤ `edhrecTop1Rank` top1000, else ≤ `edhrecTop2Rank` top5000, else longtail; anything else unranked. formatProfile is competitive when `legalities.standard`, `.pioneer` or `.modern` is exactly "legal", else edh when `legalities.commander` is "legal", else casual; "restricted", "banned", "not_legal", a missing key or non-object legalities count as not legal. - **S4.1d5 (age).** A date is valid by `windowDates`'s rule: 'YYYY-MM-DD' that round-trips through `Date.UTC` (so 2026-02-30 and years 0000 to 0099 are rejected). Otherwise modern-era iff `released_at >= modernEraStart` (ISO strings compare as dates), else vintage-era. Either date invalid gives unknown. Age is the printing's own `released_at`, so a 2025 reprint of a 1994 card is recent (F4).
