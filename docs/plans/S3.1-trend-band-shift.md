> Story: [Notion S3.1](https://app.notion.com/p/394a7227e26f8137badbc3caf51b6ac2) · Design: [F3 Market Adjustments](https://app.notion.com/p/394a7227e26f81d0b70fed71139e30a2) (Approved, Josh 2026-10-20; Functionality, Engine API, W1, W2, Fields, Tier-2 examples) · [F1 Price Recommendation Engine](https://app.notion.com/p/394a7227e26f813e8e97f395b70c0eb3) (Approved; Signal definitions, Locked copy table, Worked examples, W2) · [F2 Live Evaluation Integration](https://app.notion.com/p/394a7227e26f81b7b3ccf5f51168130c) (Approved; the server path) · PR: #20 · Critique: docs/critiques/C1-2026-10-04-phase1-designs.md#C1.10, C1.11, C1.25, C1.34, C1.36, C1.37, C1.41, C1.42, C1.47, C1.61 · docs/critiques/C3-2026-10-08-s1.1-plan.md#C3.7

## Objective
Build Tier 2, part 1, of the recommendation engine: the trend band shift. `computeTieredRecommendation(input, market, params)` returns `{ tier1, tier2 }`, where tier1 is S1.2's result unchanged and tier2 applies F3's thresholds: widen (low confidence only, 1.5×), then the Buy-side asymmetry, then the trend shift (`slope30dPct × windowDays × trendShiftFactor`, clamped to ±fairBand, 0 inside the dead zone). Tier 2's reason gains at most one trend clause from F1's locked copy. `TIER2_ENABLED: false` joins `RECOMMENDATION_PARAMS` and the `PARAMS_VERSION` hash, `computeRecommendation` serves Tier 1 while it is off, and F2's server path switches to the tiered call. No log is written (pivot, S3.1d2); volatility widening, staleness and the shock annotation are S3.2's.

**Pivot (F5 not approved; Josh's overnight directive, 2026-10-20).** F3 and this story say S3.1 depends on S5.1, so F5's log exists when F3 merges. F5 is Draft. This story builds the Tier 2 engine, `computeTieredRecommendation`, `TIER2_ENABLED: false` and the server-path switch, but writes no log and adds no console fallback. AC-4's logging half (`kind`, `rawKind`, `adjustedKind`) moves to S5.1, which consumes `{ tier1, tier2 }`. AC-4's deep-equal stays. With the flag off the served result is Tier 1, so users see no change. Recorded on Notion F3, S3.1 and S5.1 (2026-10-20).

## Sequence Diagrams

### W1: Served recommendation through the tiered call (F3 W1, W2 without the log)
```mermaid
sequenceDiagram
    actor U as User
    participant FE as Front End
    participant SV as Server (buildEvaluation)
    participant SF as Scryfall API
    participant DB as Supabase DB
    participant EN as Engine
    U->>FE: Card, finish and asking price
    FE->>SV: Open the result page
    SV->>SF: Prices for the printing
    SV->>DB: History for (scryfall_id, applied finish)
    SV->>EN: computeTieredRecommendation(input, market), two arguments
    alt Asking price or finish invalid
        EN-->>SV: Throws InvalidRecommendationInputError (unchanged)
    else Tier 1 is insufficient_data
        EN-->>SV: tier1 insufficient_data, tier2 null
    else Enough data
        EN-->>SV: tier1 (S1.2 result) and tier2 (adjusted thresholds, trend clause)
    end
    SV->>EN: servedRecommendation(tiers)
    alt TIER2_ENABLED false (this story)
        EN-->>SV: tier1
    else TIER2_ENABLED true (a later code change)
        EN-->>SV: tier2, or tier1 when tier2 is null
    end
    SV-->>FE: Panel from the served recommendation; tiers kept on the Evaluation for S5.1
    Note over SV,DB: No log write and no console fallback (pivot, S3.1d2)
```

### W2: Inside the engine (one tiered call)
```mermaid
sequenceDiagram
    participant EN as computeTieredRecommendation
    participant T1 as Tier 1 (S1.2 path)
    participant T2 as tier2.ts
    participant RS as reason.ts and copy.ts
    EN->>T1: validate, window, market price, count, signals, bands
    T1-->>EN: tier1 Recommendation
    alt tier1.kind is insufficient_data
        EN-->>EN: tier2 = null
    else
        EN->>T2: tier1 confidence, trendDirection, slope30dPct, params
        Note over T2: confWiden = 1.5 when confidence is low, else 1.0; volWiden = 1.0 until S3.2
        Note over T2: fairBand = fairBandPct x wideningFactor; buy = -(fairBand / 0.6); wait = +fairBand
        Note over T2: shift = slope30dPct x windowDays x 0.5, clamped to +-fairBand, 0 when flat
        Note over T2: buyBp = round((buy + shift) x 100), waitBp = round((wait + shift) x 100)
        T2-->>EN: wideningFactor, bandPct, buyBp, waitBp
        EN->>EN: kind = bandKind(deltaBp, adjusted), strict, equality is Fair
        EN->>RS: kind, deltaBp, bandPct, confidence, count, trend clause when rising or falling
        RS-->>EN: primary clause; trend clause; caveat.
        EN-->>EN: tier2 = tier1 with kind, reason, bandPct, wideningFactor and thresholds replaced
    end
```
